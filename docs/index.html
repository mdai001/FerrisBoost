Gradient boosted trees for large tabular data.

FerrisBoost is a Rust-backed gradient-boosted tree library with XGBoost-compatible model interchange for supported objectives and a Python API with familiar parameter names. Training semantics can differ for some objectives; see the Python API How-To.

FerrisBoost is an independent, column-blocked gradient boosting implementation licensed under Apache 2.0. It provides XGBoost-compatible model interchange for supported objectives, but does not use or depend on the XGBoost runtime and is not affiliated with or endorsed by the XGBoost project or its maintainers.

Why FerrisBoost

FerrisBoost uses a column-blocked histogram engine to process features in cache-conscious chunks, keep working memory bounded, and skip unselected columns during GPU histogram construction.

File-first pipeline

Train directly from Parquet, CSV, CSV.gz, pandas DataFrames, PyArrow tables, or NumPy arrays without constructing an intermediate DMatrix.

Adaptive GPU memory

The planner selects full residency, hybrid caching, or streaming execution based on the workload and available VRAM.

Deterministic modes

gpu_math="exact" produces byte-identical CPU/GPU models. Fast mode remains deterministic.

XGBoost interchange

Supported models save and load through an XGBoost-compatible JSON representation.

Install

pip install ferrisboost

The portable wheel supports CPU use without an NVIDIA driver. CUDA is loaded only when a GPU device is requested.

Quick start

import ferrisboost as fb

model = fb.train(
    {
        "objective": "binary:logistic",
        "device": "cuda",
        "max_depth": 6,
    },
    "train.parquet",
    label="target",
    num_boost_round=100,
)

prediction = model.predict("test.parquet")

Observed performance

On the standardized HIGGS and Epsilon Parquet workloads reported in the README, FerrisBoost used 0.27–0.46× XGBoost setup time, 0.29–0.47× peak host RAM, and 0.43–0.72× combined RAM plus active VRAM on GPU. CPU training used 0.53–0.84× XGBoost CPU training time and GPU-fast training 0.37–0.73× XGBoost GPU training time. These results describe the tested workloads, not universal guarantees.

Changelog

See the Python API How-To for details.

0.0.9 (unreleased)

The current development candidate adds the features below. They are not in the published PyPI wheels or Rust crate; release and platform validation are still pending.

  • Depthwise max_leaves, path-based interaction_constraints, feature sampling weights, and opt-in gradient-based row sampling.
  • Additional scalar regression and classification objectives, plus Cox and AFT survival objectives.
  • Rust custom metric and scalar custom objective extension points with batch adapters for Python.
  • Workload-scoped GPU refinements include coalesced split-input uploads, initialization-selected numeric split masks, and parallel large-row CUDA fast gradient sampling.
  • Single-GPU execution remains the supported device scope. Survival objectives and Python custom objectives support CPU and CUDA exact; CUDA fast is unsupported for them. Lossguide is deferred.

  • Up to 65,534 categories per feature (was 254).
  • Wide bins and many categories train on CPU and GPU.
  • GPU speed optimizations.
  • Fixed: rare split differences from XGBoost when two candidates have nearly equal gain.
  • Named categories: pandas categories and Arrow / Parquet string dictionaries are stored in the model (XGBoost cats layout); named input is re-coded by value, and unseen categories raise ValueError.
  • CSV text columns declared categorical train as named categories.
  • Changed: models with integer categories now look up plain integer input by value, not as codes.
  • Changed: Arrow integer dictionaries are read by value for models without category lists, as Parquet files are.
  • Changed: pandas and Arrow integer columns are read by value like files (NumPy stays codes).
  • Fixed: sklearn estimators handle Arrow dictionary columns like train (nulls are missing).
  • Fixed: cache_path / cache_budget_bytes with unsupported input (such as several Parquet files) now raise instead of being ignored.
  • Fixed: integer category values are mapped by value during continuation, without stale category state on estimator refit.
  • Fixed: Arrow dictionary training, evaluation and prediction work without pandas installed.
