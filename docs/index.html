FerrisBoost trains large tabular models directly from Parquet, CSV, Arrow, or NumPy. Its Rust data plane and adaptive CUDA backend keep setup, host memory, and GPU execution under control.

train.py

import ferrisboost as fb

model = fb.train(
    {
        "objective": "binary:logistic",
        "device": "cuda",
        "gpu_math": "exact",
        "max_depth": 6,
    },
    "train.parquet",
    label="target",
    num_boost_round=100,
)

pred = model.predict("test.parquet")

Designed around the data path

Spend less time preparing data.
More time boosting.

FerrisBoost treats ingestion, quantization, memory planning, and training as one coordinated pipeline instead of a chain of full-data materializations.

01

File-first Rust pipeline

Stream Parquet, CSV, and CSV.gz directly into quantized column blocks. Multi-file inputs, directories, and globs preserve deterministic ordering without constructing an intermediate Python training matrix.

ParquetCSVCSV.gzArrowNumPy
02

Adaptive VRAM

The planner chooses full residency, hybrid caching, or streaming execution from the workload and available GPU memory.

03

Determinism by design

gpu_math="exact" preserves byte-identical CPU/GPU models. Fast mode remains deterministic when maximum throughput matters.

04

Physical column sampling

Unselected features are omitted from histogram initialization, accumulation, subtraction, and device-to-host output.

05

Model portability

Supported objectives serialize to standard XGBoost-compatible JSON, keeping training and prediction backends independent.

Performance in context

Ratios are FerrisBoost divided by the corresponding XGBoost backend. Values below 1.0× favor FerrisBoost. Results cover standardized HIGGS Parquet and Epsilon CSV workloads.

These observations describe the tested datasets and hardware, not universal guarantees. Metric scoring is excluded from training time. Combined memory is a secondary observed footprint indicator.
